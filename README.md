# Keystone

A tamper-evident, append-only log in Go. Keystone records opaque byte entries and lets a verifier detect, after the fact, whether any committed entry was modified, deleted, truncated, or reordered.

> **Status: early.** The hashing core (`keylog/`) and the crash-safe file store (`storage/`) are implemented and tested. The `keystone` CLI (`append`, `verify`, `proof`) is still a stub. Next: a Merkle tree with inclusion and consistency proofs, then signed checkpoints.

## Guarantees (v1)

- **Tamper evidence.** Modifying, deleting, truncating, or reordering a committed entry is detected against a previously retained log head.
- **Crash safety.** An append interrupted by a crash or power loss never corrupts committed entries. On open, the store recovers to the last complete record.
- **Interoperable hashing.** Leaf hashes are byte-identical to RFC 6962 and Go's `golang.org/x/mod/sumdb/tlog`, so future proofs work with existing transparency-log tooling.

Out of scope for v1: preventing split views (that needs signed checkpoints and external witnesses), tamper *proofing*, confidentiality, multiple writers, and replication. The full threat model is in [ADR-000](docs/adr/000-goals-threat-model.md).

## Design

### Hashing ([ADR-001](docs/adr/001-canonical-serialization.md))

Every hash is SHA-256 with a one-byte domain-separation prefix, fixed for the life of a log:

| Hash | Definition |
|---|---|
| Leaf | `SHA-256(0x00 ‖ entry)`, identical to `tlog.RecordHash` |
| Interior node (reserved for the Merkle tree) | `SHA-256(0x01 ‖ left ‖ right)` |
| Chain link | `SHA-256(0x02 ‖ prev ‖ leaf)` |

A leaf is exactly the caller's bytes, with no index, timestamp or previous hash inside it. Chain metadata lives in the storage framing, so the Merkle tree can hash today's leaves without migrating any data.

### On-disk format ([ADR-002](docs/adr/002-file-format.md))

```
file   := "keystone-log-v1\n" record*
record := len (uint32, big-endian) ‖ payload ‖ chain (32 bytes)
```

- **Durability:** each record is one `write(2)` on an `O_APPEND` descriptor, then `fsync`, before `Append` returns. The parent directory is fsynced when a log is created, and files are created with mode `0600`.
- **Fail-stop:** after any write or fsync error the store refuses further appends; reads keep working.
- **Recovery on open:** a forward scan validates every frame and recomputes the chain.

| Found on open | Action |
|---|---|
| Incomplete final frame (a torn append that was never acknowledged) | Truncate to the last complete record and fsync |
| Length field above the 16 MiB record limit | Fail with `CorruptError` |
| Complete frame whose chain hash doesn't match | Fail with `CorruptError` naming the record; the bytes stay in place as evidence |

## Usage

```go
s, err := storage.Open("audit.log") // creates the log, or recovers an existing one
if err != nil {
	log.Fatal(err) // *storage.CorruptError if a committed record fails validation
}
defer s.Close()

ctx := context.Background()
idx, err := s.Append(ctx, []byte(`{"event":"login","user":"alice"}`)) // durable once it returns
if err != nil {
	log.Fatal(err)
}
entry, err := s.ReadLeaf(ctx, idx) // the exact bytes that were appended
if err != nil {
	log.Fatal(err)
}
fmt.Printf("record %d: %s\nhead: %x\n", idx, entry, s.Head())
```

## Testing

- Known-answer vectors for leaf and chain hashes, generated by an independent Python implementation (`keylog/testdata/vectors.txt`).
- An equivalence test of `keylog.LeafHash` against `tlog.RecordHash` on random inputs.
- Fuzz tests for the record decoder and crash recovery (`FuzzOpen`, `FuzzRecovery`).
- A golden file that pins the on-disk format (`storage/testdata/golden.log`).

```sh
go test ./...
go test -run='^$' -fuzz=FuzzRecovery ./storage
```
